## Defects found
(ordered by likely damage to the plan if left uncorrected)

1. **Claim 6 (highest): coefficient-to-effect mapping inverted.** The plan's parenthetical "alpha = 0.1 retrieval vs beta = 0.9 time" swaps the paper's assignment. In MOOM (arXiv 2509.11860), **α=0.1 is the temporal-decay weight (time-induced forgetting)** and **β=0.9 is the retrieval-reinforcement weight (retrieval-induced strengthening)**. All numbers match; larger = stronger. The qualitative conclusion (retrieval-induced strengthening dominates) is correct because β>α. But anyone using the plan to set the forgetting equation parameters would wire 0.1→retrieval and 0.9→time, which is backwards — the exact opposite strength ordering the paper reports.

2. **Claim 7: "LoCoMo LLM-judge 93.05" is a misattribution.** EverMemOS's LLM-judge reliability figures are Cohen's κ = **0.891 (LoCoMo)** and **0.979 (LongMemEval)**, computed vs 5 human annotators over 25 Q&A pairs each. The **93.05** is EverMemOS's **overall LoCoMo accuracy** in Table 1 (†9.2% vs Zep), not a judge metric at all. The plan grafts a performance number onto a judge-reliability claim. If the plan cites 93.05 as judge agreement, that is factually wrong; the correct judge-reliability number is κ≈0.89–0.98, which already confirms the qualitative claim (κ>0.89) without the fabricated-looking 93.05.

3. **Claim 3: condition-stripped.** "54 poisoned entries accepted at trust=1.0" holds only for the **Gemini-2.0-Flash** experiment (Experiment 2); the GPT-4o-mini experiment rejected all 23 candidate entries. The plan omits the model, and omits that trust=1.0 is the guard agent's *composite credibility* (code-safety + semantic-relevance + answer-agreement) — i.e., a confidence filter, which is exactly why 54 confident attacks passed. Reading it as the GPT-4o-mini run would be wrong.

4. **Claim 2: two experimental setups silently conflated.** "62% → 6.7%" is the empty→(relevant-initial-memory) jump at retrieval k=3 (Table 1). "6% → 38%" is a *different* setup — the retrieval-k sweep with **6 initial memories + 4 indication prompts** (Table 2, k=3→5→10). The plan presents them as one continuous trajectory ("collapses ... then climbs"), but 6% is a k=3 figure from a different configuration than the 6.7% it is nominally continuous with. All underlying numbers are correct and present; the narrative splicing is loose. Also "53%" is actually 52.94%.

5. **Claim 5: benign-but-imprecise wording.** The plan says "bounds drift at O(N·eps_step) with periodic reconciliation". This matches the theorem statement exactly. The only trap: N must be read as the *reconciliation interval* (steps between reconciliations), not a total-horizon count — the theorem's whole point is that drift is bounded by the window size N, independent of the long horizon T. eps_step is the per-consolidation-step error bound. Confirmed, but flag so the implementer wires reconciliation cadence (N) into the drift-budget equation rather than a fixed budget.

6. **Claim 4: "M(u,a,t) predicate" is a set-membership condition, not a separately named predicate.** The paper's eq (3) defines the admissible-fragment set M(u,a,t) := {m | A(m)⊆A(u,t) ∧ R(m)⊆R(a,t)}; the plan calls it a "predicate" — functionally fair (it is a filter condition enforced at read time), but a purist transcription would call it the fragment-access membership condition. Revocation = edge removal from G_UA(t), enforced by re-filtering at the next read. No substantive error.

7. **Claim 1: conditions worth restating.** The 98.2/76.8 are averages over three agents/four datasets *under empty shared memory* — the high-end threat case the plan already flags as conditional. Confirmed verbatim; the plan's own framing ("Poisoning is real but conditional") is the right read.
